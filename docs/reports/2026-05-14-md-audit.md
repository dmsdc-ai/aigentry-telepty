### Issues

- **A-1** (line 79–92): Cites `ADR 2026-05-05-telepty-devkit-boundary §6.2.1` four times without disclosing that the ADR lives in the **sibling repo** `aigentry-orchestrator/docs/adr/`. - **A-4** (Overview, lines 4–6): No package version reference — minor, but `0.3.5` is unstated; `CHANGELOG.md` is the source of truth and is not linked.

## Cross-file observations

1. **Layered-instruction pattern inconsistency** — `GEMINI.md` (7 lines, `@AGENTS.md` stub + Gemini-specifics) is the canonical pattern per ADR-MF #6. `CLAUDE.md` (101 lines, ~70% duplicate) is not. Recommendation: either bring `CLAUDE.md` into stub form *or* explicitly document why it is not (e.g. "Claude reads from cwd up; we want X without re-resolving AGENTS.md"). Currently the divergence is implicit and the cost is duplicate maintenance + drift.
2. **Drift-prone fact concentration** — All 7 stale facts in `CLAUDE.md` are *self-dating* (LoC counts, test counts, version ranges). `AGENTS.md` avoided this trap by not embedding measurable counts. Recommendation: adopt the AGENTS.md style across all three files — describe shape, not metrics.
3. **Cross-repo ADR refs** — `AGENTS.md` lines 79–92 references an ADR that lives in `aigentry-orchestrator`. This is acceptable per dispatch guidance ("정합성 ↑") but **must disclose the path** so future readers don't dead-end.
