# #757 — launchd kickstart orphan after version-change restart

## Reproduction

Hermetic launchd repro used a scratch label (`com.aigentry.telepty-test-757x-*`), scratch `HOME`, and an OS-assigned port. Production label and port 3848 were not touched.

Bare scratch `launchctl kickstart -k` did **not** orphan: the scratch job reached `job state = running` and its launchd-launched pid owned the port.

The production-like failure reproduced once a detached daemon pre-owned the scratch port, matching the version-change restart path:

```text
ORPHAN_META_BEFORE_KICK {"pid":28544,"port":63830,"version":"0.7.0"}
ORPHAN_PS_BEFORE_KICK 28544     1 Ss   telepty-daemon
AFTER_FIRST_KICK_META {"pid":28544,"port":63830,"version":"0.7.0"}
AFTER_FIRST_KICK_JOB
  state = not running
  last exit code = 0
  job state = exited
LAUNCHD_OUT_TAIL
  [DAEMON] telepty daemon already running on port 63830 (v0.7.0). Exiting.
KILLED_ORPHAN 28544
RECOVERED_META {"pid":28963,"port":63830,"version":"0.7.0"}
RECOVERED_JOB
  state = running
  pid = 28963
  job state = running
```

Root cause: supervised installs still had detached restart sources. `restartDaemonGraceful()` used `startDetachedDaemon()` on version/capability restart, and `scripts/postinstall.js` always spawned `telepty daemon` detached after stale global upgrade cleanup. Once that detached process owned the port, launchd's next kickstart lost the bind race and exited 0, leaving the detached pid serving outside the job.

## Fix

- `src/supervisor.js`
  - Added `restartSupervisorDaemon()` for launchd, root systemd, user systemd, and Windows scheduled tasks.
  - Detection now also recognizes user-level systemd units generated by `install.js`.
- `cli.js`
  - `restartDaemonGraceful()` detects a supervisor on restart paths.
  - If supervised, it waits for supervisor auto-restore or restarts through the supervisor.
  - It does **not** fall back to `detached + unref` for supervisor-managed installs.
  - Unsupervised installs keep the existing detached restart behavior.
- `scripts/postinstall.js`
  - Refactored to testable seams.
  - Stale global upgrade now restarts through the detected supervisor when present.
  - Detached postinstall spawn remains only for unsupervised installs.
- `CHANGELOG.md`
  - Added `## Unreleased` #757 entry.
