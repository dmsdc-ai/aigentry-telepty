## Root causes

### RC-1 — `randomPort()` picks an unchecked random port (TEST HARNESS bug) — **dominant**

`test-support/daemon-harness.js`:

```js
function randomPort() {                       // line 71
  return 30000 + Math.floor(Math.random() * 20000);   // 30000–49999, never probed
}
...
const port = options.port ?? randomPort();    // line 97
const child = spawn(process.execPath, ['daemon.js'], { env: { ...PORT: String(port) } });
await waitFor(async () => {
  if (child.exitCode !== null) throw new Error(`Daemon exited early.\nstdout:\n...\nstderr:\n...`); // line 148
  ...
}, { timeoutMs: 7000 });
```

The harness spawns each test daemon on a **random, unverified** port instead of an OS-assigned free port (`:0`). When the port is unavailable, `daemon.js` exits and the harness throws **"Daemon exited early"**; the first such test eats the full 7 s `waitFor` timeout and its file-siblings cascade-fail instantly.

**Evidence — ubuntu (EADDRINUSE):**
```
🚀 aigentry-telepty daemon listening on http://127.0.0.1:34022
stderr:
[DAEMON] Port 34022 is already in use by another process.
  at startTestDaemon (test-support/daemon-harness.js:146:3)
  at TestContext.<anonymous> (test/cross-host-inject.test.js:41:13)
```

**Evidence — windows (EACCES on reserved ports):**
```
Error: Daemon exited early.
Error: listen EACCES: permission denied 127.0.0.1:49884   (also :49731, :49726, :49712)
```
All four windows EACCES ports are **49xxx — the top of the `randomPort()` range**, which overlaps the **Windows WinNAT / Hyper-V excluded port ranges** (those ports cannot be bound by a normal process). So on Windows the same bug fails *systematically* rather than probabilistically, taking down every daemon-dependent file it lands on.

**Why macOS passes:** macOS has no reserved-range problem and the random collision rarely hits; ubuntu collides occasionally (flaky); windows hits reserved ports often (consistent).

### RC-2 — Windows CRLF / git autocrlf on golden fixtures
`snippet bodies are LF-only` (expected `false`) and `golden snippet fixtures match runtime output` fail on windows; the expected fixture text in the log is full of `\r\n`. `actions/checkout` on windows uses `core.autocrlf=true`, so `tests/snippet-protocol/v1/*.md|json` are checked out with CRLF. (Also a latent risk for the trailing `git diff --exit-code tests/snippet-protocol/v1/` gate.)

### RC-3 — Unix domain sockets unavailable/denied on Windows
```
Error: listen EACCES: permission denied C:\Users\RUNNER~1\AppData\Local\Temp\telepty-test-uds-...sock
```
The aterm UDS tests assume a bindable `.sock`; Windows node UDS on the temp path is denied.

### RC-4 — Windows path / home resolution in broker-cli (+ ssh-peers)
```
Error: ENOENT: no such file or directory, open 'C:\Users\RUNNER~1\AppData\Local\Temp\...\.telepty\broker.json'  (also broker-acl.json)
```
plus AssertionErrors in `listBrokerRemoteSessions`, `list includes broker sessions`, `listSshPeers` ×2, `getSshPeerHandle`, `remoteInject (#411)` — consistent with Windows path-separator / home-dir / `.telepty` creation differences when reading/writing `peers.json`/`broker.json`. **Needs a coder to repro on Windows** to separate "real Windows bug" from "test setup assumes POSIX paths."

### RC-5 — Windows PTY/TUI bootstrap timing
Timeouts (no assertion): `telepty allow queues first fake-claude inject` (10991 ms), `interactive update returns to the TUI` (7614 ms), `interactive menu recovers from a terminal EIO` (7421 ms). Windows node-pty / fake-claude spawn + bootstrap is slower / behaves differently than POSIX.

## Recommendation to restore a trustworthy gate (priority order)

1. **P0 — Fix `randomPort()` (test harness).** Change `startTestDaemon` to bind ephemeral port `:0` and read the OS-assigned port back from `daemon.js` (requires `daemon.js` to accept `PORT=0` and report the bound port; if not, fall back to a retry-on-EADDRINUSE/EACCES loop). **This one fix turns ubuntu green, removes the bulk of windows red, and — most importantly — eliminates the flakiness, which is the worst property of a release gate.** Pure test-infra change; not a product bug.
2. **P1 — CRLF**: `.gitattributes` forcing LF on `tests/snippet-protocol/v1/**` (or `core.autocrlf=false` at CI checkout). Also hardens the trailing `git diff --exit-code` gate on Windows.
3. **P1 — OS-gate UDS tests** on win32 (unix_socket delivery is not a Windows-supported path).
4. **P2 — Windows broker/ssh path bug (RC-4)**: a coder must reproduce on a Windows runner to decide real-bug-fix vs POSIX-only test setup (~9 tests).
5. **P2 — Windows PTY/TUI timing (RC-5)**: raise timeouts / investigate node-pty spawn; OS-gate if intractable (3 tests).

**Fastest path to a trustworthy green gate:** do **#1** first (largest blast-radius, kills the flake), then the quick wins **#2/#3**. **#4/#5** need real Windows-runner reproduction. If an immediate green gate is required before #4/#5 land, **quarantine** the remaining windows-only failing files (UDS, TUI, broker) with tracked skip markers rather than leaving the whole matrix red.

**Analyst does not apply any of these** — all are delegated to a coder by the orchestrator.
