# Strict exact session bus effects

Opt-in strict principal mode exposes `GET /api/bus/sessions/:exactId` as a bounded signed HTTP adapter. It is separate from the read-only event stream and legacy `/api/bus` publishing. The upgrade requires a header-only assertion with exact `session.bus` SID grant, current epoch, `websocket` transport, raw path and empty body digest. The connection grant does not imply ownership, session reads, state mutation or injection authority. Literal socket loopback or actual TLS, existing Origin/peer restrictions, finite proof expiry, record/epoch/credential/owner fences, connection/frame limits, cancellation and backpressure apply through the same transport used by strict input.

The initial `telepty.bus-effect-stream/v1` identity supplies `connection_id`, SID, epoch, expiry and max 64 frames. Every application frame must carry that ID and the next integer sequence. Only these operations exist:

- `state_report`: body has required nonempty `phase` (max 128 UTF-8 bytes), optional `current_task`/`blocker` (max 4096 bytes each), optional boolean `needs_input` and nonnegative safe-integer `seq`. It forwards the signed body unchanged to exact `POST /api/sessions/:id/state`, action `session.state`. Pre-reservation policy and actual HTTP authorization both require the stored owning principal; an operator with a grant for another owner's session is still refused.
- `routed_turn`: body has `prompt` (max 4096 UTF-8 bytes), current `expected_epoch`, `exact_target:true`, boolean `no_enter` and optional external approval. It forwards unchanged to exact `POST /api/sessions/:id/inject`, action `session.inject`. Normal exact inject, approval, delivery and audit gates remain authoritative. No claimed `from`, `reply_to`, alias, host suffix routing or caller-selected target is accepted.
- `receipt`: requires an explicit `effect` of `state_report` or `routed_turn` and the prior idempotency key. It only queries that connection actor's exact SID/epoch/effect namespace.

Effects also carry `idempotency_key` (16–128 URL-safe characters), `body` and an HTTP `assertion`. Before creating any durable intent, the shared verifier's nonconsuming inspection checks the exact POST path/action/body digest/epoch, grant, replay status and the same key/principal/audience as the connection. State effects additionally require that principal match the stored owner before consuming receipt capacity. The actual loopback HTTP middleware then rechecks and consumes that same nonce before any effect. No application principal is synthesized from frame claims. The adapter never calls legacy `busAutoRoute` or enrolls sockets in raw `busClients`.

Receipts use `telepty.bus-effect-receipt/v1`, with effect, receipt ID, SID/epoch, state and an allowlisted result. State receipts expose only success/sequence or a bounded refusal code; no semantic/transport response metadata. Routed-turn receipts have the existing strict-input receipt projection. `consumption` and `reply` remain `unknown`. Pending after restart, timeout, malformed successful response, server/storage error or lost response is `outcome_unknown`; nothing retries automatically. Query the same namespace/key. Durable fingerprints bind effect+HTTP target+body, and record/key namespaces bind actor key/audience, SID and epoch. State and turn can safely use the same caller key without collision. Records contain digests and bounded result metadata, never raw state/task/prompt text or assertions.

Strict input now wraps this common transport. Its existing `strict-input/v1` key derivation, body-only fingerprint, schemas, frame API and receipt behavior are preserved, including pre-existing durable receipts. Both adapters share the existing 512-record storage bound. Bus mutation support is intentionally limited to these two explicit operations: arbitrary app relay, target lists, legacy turn-request envelopes, publishing trusted daemon events and bus state subscription are unsupported. Use the separate scoped read-only events endpoint for event reads. No bus CLI is included in this slice.
