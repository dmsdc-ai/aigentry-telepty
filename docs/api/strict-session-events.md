# Strict scoped session events

In opt-in strict principal mode, `GET /api/events/sessions/:exactId` upgrades to a read-only WebSocket. It requires a header-only `x-telepty-principal` Ed25519 assertion with action `session.events`, exact SID grant, current session epoch, transport `websocket`, exact raw GET path and empty JSON body digest. The same daemon verifier/replay cache protects HTTP, owner, observer and event proofs. The caller must own the stored session principal, or be an operator with that explicit read grant. Reachability and Origin checks can only narrow access. Bearer/JWT/session-token fallbacks, query credentials, aliases, host suffix parsing and automatic registration are unsupported.

The first frame is `telepty.read-only-session-events/v1`, with type `session_events`, exact `session_id`, `session_epoch`, `read_only:true` and `expires_at`. There is no replay or initial state snapshot. Each subsequent `telepty.session-event/v1` frame contains only a fixed approved type, the authorized SID/epoch, daemon publication timestamp, `observation_only:true` and `foreign_session_identity_verified:false`. `session_health` may additionally expose the enumerated `health_status` CONNECTED, STALE, DISCONNECTED or UPSTREAM_STALLED. This is transport metadata, not agent identity, readiness or task completion proof.

Approved event types are `session_connect`, `session_reconnect`, `session_disconnect`, `session_health`, `session_state_report`, `session_takeover`, `session.idle`, `inject_failed`, `peer_inject_blocked`, `mailbox_delivered`, `mailbox_delivery_failed` and `mailbox_delivery_unknown`. Unknown event types are dropped. State-report events mean only that the daemon published a report event: caller-provided phase, task, blocker and source text are never projected.

Only the daemon's `broadcastSessionEvent` producer feeds this transport. Sockets never enter legacy `busClients` or `session.clients`. Arbitrary bus publishing, even with a claimed daemon sender or matching SID, cannot enter the trusted feed. Nested transport/semantic blocks, caller extensions, cross-session references, prompt text/hashes, command, cwd, PID, thread/sender details, credentials and proofs are excluded by explicit projection. Other legacy producers outside this trusted hook are not included; this is a scoped event subset, not a complete legacy bus implementation.

Connections expire with the signed assertion (at most 60 seconds), and close on record replacement, closing, epoch/credential/owner-generation changes, owner socket changes, stored-principal changes or daemon shutdown. Reconnect requires a fresh proof. There are at most 64 event sockets globally and 8 per principal/session. Frames are capped at 4 KiB and sockets terminate before exceeding 128 KiB buffered output. Every client application message closes the socket: no subscribe, publish, state report, turn routing, input or resize operation is supported. No automatic retries or event durability are implied.

Legacy `/api/bus` remains unavailable in strict mode. This endpoint does not complete strict full-duplex bus support. Versioned client/CLI event subscription can use the existing principal signing helper; legacy global `listen`/`monitor` does not automatically gain scoped access.
